# analysis/ — 위험 유형 분류 모델 (담당: 박현준)

> **중요: 이 폴더는 서비스 코드(`harinote/`)를 변경하지 않는다.**
> 점수 산식·엔진은 그대로 두고, 데이터 분석으로 산식의 사각지대를 찾아
> "적용하면 무엇이 바뀌는지"까지 검증한 제안 패키지다.

## 왜 했나

- 제안서 2단계 약속: "관광지 위험 유형 분류 — 규칙 기반 → ML 전환"
- 심사 예상질문 "AI가 정말 필요한가? 규칙 기반 필터링 아닌가?"에 대한 답 마련
- EDA 결과: 현행 envType 휴리스틱은 관광지 775건 중 **57%(443건)를 outdoor_general로 뭉뚱그림** — 이 안에 사찰·산촌체험마을 등 실질 산악·오지가 섞여 있음

## ⚠️ 먼저 읽을 것 — 06/07/09/12는 안전점수 가중치의 근거가 아니다

클러스터링 입력 피처가 `safety_engine.compute_safety_score()`의 출력
(`s_heat`·`s_rain`·`s_fire`·`s_medical` …) 그 자체다:

```
weights.ts 가중치 → 감점 → 클러스터링 피처 → 군집 → "데이터가 유형을 발견했다"
      └──────────────────── 순환 ─────────────────────┘
```

가중치가 군집을 만들었으므로 **군집이 가중치를 정당화할 수 없다.** 분류기(09)도 라벨이
자기 군집이라 acc 0.895는 예측 성능이 아니라 **정보 압축률**이다("엔진 출력으로 만든
군집을, 엔진이 안 쓰는 원천 피처로 89.5% 복원 가능").

**그럼 무엇이 남는가.** 실제로 서비스를 바꾼 산출물은 `envtype-overrides.json` 93곳
보정 하나이고, 그 판단 근거는 군집이 아니라 **표고(SRTM 30m)와 응급실 거리라는 원천
피처**다 — "표고 400m 이상인데 규칙이 일반 야외로 분류한 곳". 이건 순환이 아니다.

발표에서는 이렇게 말해야 한다:

> ~~"클러스터링으로 위험 유형을 발견했다"~~
> → "규칙 기반 분류가 표고 400m 이상 산지 93곳을 '일반 야외'로 뭉뚱그리고 있었고,
>    표고·응급실 거리로 그것을 찾아 보정했다"

축·가중치의 실제 근거 지도는 [25_safety_evidence_map.md](25_safety_evidence_map.md) 참조.

## 외부 검증 (강원 119 데이터) — 순환 없는 유일한 실증

- **자연장소 사고는 구조가 유의하게 느림: 시군 내 쌍대 비교 +3분, Wilcoxon p=0.0008**
  → **응급의료 접근성 축의 실증 근거.** 군집·엔진과 무관하게 사고 데이터만으로 성립한다
- 수난사고 시군 분포 ↔ 수변·해안 관광지 분포 **rho=0.49, p=0.038** (탐색적 — 40건 소표본,
  다중검정 보정 시 경계선). envType 배율의 *방향*만 지지하고 *크기*는 지지하지 않는다
- 고지·오지형 ↔ 시군 구조시간: **판정 불가** (사고 데이터에 좌표 없음 — 시군 집계 한계)

세 번째 항목이 구조적 제약이다. 사고에 좌표가 없어 공간 최소단위가 시군 18개이므로
**envType별 가중치는 어떤 방법으로도 이 데이터로 실증할 수 없다**
(`19_score_calibration_design.md:46`이 이미 보정 대상에서 제외 선언).

## 클러스터링이 나눈 6개 유형, 그중 "고지·오지형"

| 유형 | n | 특징 |
|---|---|---|
| 근교전천후 | 312 | 저지대·의료 양호 |
| **고지·오지형 ★** | **132** | **평균 표고 536m·응급실 19.5km — 현행 규칙은 전부 "일반 야외" 취급** |
| 산악 | 123 | 산불·강풍 가중 (현행 규칙과 일치) |
| 해안 | 100 | 강풍 가중 (일치) |
| 수변 | 91 | 호우 가중 (일치) |
| 실내 | 17 | 기상 영향 낮음 (일치) |

4개 유형이 현행 규칙과 수렴한 것은 **필연이다** — 피처가 그 규칙(`ENV_WEIGHT`)이 만든
감점이기 때문이다. 의미가 있는 쪽은 규칙이 뭉뚱그린 구간을 표고·응급실 거리로 갈라낸
**고지·오지형 132건(17%)**이고, 그중 표고 400m 이상 93곳이 실제 보정으로 이어졌다.

## 서비스 적용 방안 (침습도 순)

1. **무변경 — 유형 배지**: `data/risk_types.json`(contentId→유형 775건)을 읽어 상세 페이지에
   "⛰️ 고지·오지형 — 응급의료 원거리" 배지 표시.
   → **현재 미노출.** `harinote/src/data/risk-types.json`과 `lib/tour/risk-types.ts`는 있으나
     `RiskTypeBadge.tsx`를 아무 화면도 import하지 않고 `parseRiskType()`도 호출부가 없다.
     되살리려면 순환 문제상 "유형"이 아니라 **표고·응급실 거리**를 배지 문구의 근거로 삼을 것
2. **최소 변경 — envType 보정**: 고지·오지형 & 표고 400m+ & general → mountain (93건).
   산불철 시나리오에서 −5점, 34건이 low→moderate로 — 영향 명세는 `data/envtype_fix_impact.csv`
   → ✅ **적용됨.** `harinote/src/data/envtype-overrides.json`, 로드 시점에 반영
     (`datasource.ts` → `applyEnvTypeOverrides`). **이 패키지에서 서비스를 바꾼 유일한 산출물**
3. **확장 — 분류기 이식**: `risk_type_classifier.joblib` — 신규 관광지·타지역(제주 등)에
   시나리오 계산 없이 유형+확률 할당 (이식 시 lat/lng 피처 제외 후 재학습 필요)
   → 미적용. 이식하더라도 "가중치의 근거"가 아니라 "분류 자동화"로만 쓸 수 있다

## 한계 (발표 때 선제 서술)

- **클러스터링·분류기는 가중치의 근거가 아니다** — 피처가 엔진 출력이라 순환(위 ⚠️ 절).
  가중치 근거는 [25_safety_evidence_map.md](25_safety_evidence_map.md)에 따로 정리했다
- 분류기 타깃은 자체 클러스터링 라벨 — "독립 정답 예측"이 아니라 "유형 체계의 이식 가능한 압축"
- 실내 유형 recall 0.588 (17건 소표본) → 실내는 기존 규칙 우선, 모델은 보완 (하이브리드)
- 수난 검증은 다중검정 보정 시 경계선 — "탐색적"으로 표현할 것
- **`safety_engine.py`는 v1이다** — 산불 밴드가 현행과 3.75배 다르고 산사태 축이 없다.
  06~14 산출물 전부가 구식 엔진 기준이며 v2로 재실행되지 않았다
